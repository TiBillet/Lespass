## La règle, en clair
1. **Fonction commune** (SUIVI D-3c (a)) `ecrire_la_vente_d_avoir_d_une_ligne(ligne,
   quantite, moyen_rembourse, origine)` dans `BaseBillet/services_vente.py`, **extraite
   du POST d'`emettre_avoir`** (vente AVOIR liée, article, règlement d'argent au moyen
   choisi ou au moyen Stripe d'origine, FREE pour l'offert sans doublon, encaissement,
   **puis** transition `CREDIT_NOTE`). Elle n'ouvre **pas** de transaction elle-même si
   l'appelant en a une (savepoint `atomic` permis). `emettre_avoir` l'appelle : ses
   tests D-3a restent verts **sans modification**.
2. **Avoir partiel d'une ligne entièrement offerte : permis** (SUIVI D-3c (d)) :
   `ajouter_l_article_d_avoir` accepte une quantité partielle quand
   `part_offerte == total_catalogue` (≠ 0) ; part offerte de l'avoir = total catalogue de
   l'avoir. Une ligne **en partie** offerte reste refusée en partiel. Le test D-3a
   `test_avoir_partiel_d_un_article_offert_refuse` vise une ligne en partie offerte : il
   reste vert sans modification (sinon STOP).
3. **`cancel_and_refund_resa(moyen_rembourse=None)` et
   `cancel_and_refund_ticket(ticket, moyen_rembourse=None)`** :
   - partie Stripe : inchangée (D-3b) ;
   - lignes hors Stripe : `moyen_rembourse` donné (admin) → un avoir par ligne, par la
     fonction 1 (quantité restante ; un billet → quantité 1), origine `ADMIN` ;
     `moyen_rembourse=None` (utilisateur, **D31**) → **aucun avoir**, la réservation /
     le billet passent `CANCELED` quand même ;
   - la garde « payée mais rien de remboursable » reste pour l'admin, **pas** pour
     l'utilisateur hors Stripe (D31) ;
   - `Reservation._creer_avoir` disparaît s'il n'a plus d'appelant.
4. **Les deux actions admin** passent par un **écran intermédiaire** (action Django :
   1er POST → page de confirmation listant la sélection ; 2e POST avec le formulaire →
   l'annulation) :
   - champ « Remboursé par » (CA, CC, CH, TR) **seulement si** au moins une ligne hors
     Stripe de la sélection a de l'argent à rendre (pas entièrement offerte) ; pré-rempli
     si toutes ces lignes ont le même moyen d'origine dans la liste ; obligatoire quand il
     est affiché ;
   - le moyen choisi vaut pour toute la sélection ;
   - mails d'annulation, messages de succès / d'erreur : inchangés.
5. **Booking** (D31 : seul l'utilisateur annule un booking) : plus d'avoir hors Stripe
   dans `cancel_and_refund_booking` ; `Booking._creer_avoir` retiré, `_lignes_hors_stripe`
   aussi s'il n'a plus d'appelant (`rg` avant). La partie Stripe reste (D-3b).
