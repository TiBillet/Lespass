## La règle, en clair
1. **Une vente gratuite est encaissée à 0** : `encaisser_vente(vente)` sans règlement
   (total 0 ; une part « offert » éventuelle suit la règle du service). Elle est
   numérotée : c'est une opération enregistrée.
2. **Encaisser au niveau de l'appelant qui écrit la dernière ligne** (jamais avant) :
   - réservation à 0 € du front (`TicketCreator.valider_une_reservation_a_zero_euro`,
     appelée par `ReservationValidator`) : après les lignes ;
   - **API v2** (`api_v2/serializers.py` ~l.1444-1472) : les lignes FREERES qu'elle ajoute
     après `TicketCreator` entrent dans **la même vente** (celle de `TicketCreator` si elle
     existe, sinon une vente ouverte par l'API, origine API) ; **puis** encaisser. Donc
     `TicketCreator` ne doit **pas** encaisser lui-même quand l'appelant va encore écrire :
     choisis une forme simple et explicite (paramètre, ou encaissement par l'appelant) et
     dis-la ;
   - booking gratuit (`booking/booking_engine.py` branche gratuite ~l.785-801) ;
   - panier gratuit (`BaseBillet/services_commande.py` `_finaliser_gratuit`) : après le
     passage des lignes ; **si la vente n'a aucun article** (panier de réservations
     FREERES seules) : `annuler_vente` (vente vide, sans numéro).
3. **Pas de vente sans ligne** : une réservation FREERES seule (aucune ligne de vente)
   n'ouvre pas de vente (c'est déjà le cas hors panier : vérifie-le par un test).
4. Les lignes FREERES de l'API v2 passent par `ajouter_article` (TVA par
   `_taux_tva_de_la_ligne_de_caisse`, FREE à prix non nul → « offert à montant non nul »
   du service), `qty` castée en **entier** (`"2"` → 2 ; `"2.5"` → refus clair : fiche test
   15).
5. T16 : une réservation à 0 € annulée après coup garde sa vente `REGLEE` à 0 (accepté) :
   un test le fige.
