## Ce que B-3a change
1. Hors NFC : une vente (origine caisse, point de vente, opérateur, clé = un
   `uuid_transaction` du paiement), lignes par `_creer_lignes_articles(..., vente=,
   uuid_transaction=)`, un règlement du moyen (espèces / CB / chèque) du montant
   encaissé, `encaisser_vente` en dernier, `commande.vente = vente`. Tout dans le même
   `atomic` que le statut de la commande.
2. NFC : `payer_commande` fournit la clé (`uuid_transaction_impose`) à
   `_payer_par_nfc` ; après le succès, la vente est retrouvée **par cette clé** et
   posée sur `commande.vente`, dans l'`atomic` externe. Si elle est introuvable après
   un succès : erreur franche (jamais une commande payée sans vente).
3. Idempotence : dis, preuves à l'appui, si l'interface envoie aujourd'hui une clé
   d'idempotence pour le paiement d'une table et s'il existe une garde « commande déjà
   payée ». **Ne change pas ce comportement** : rapporte-le (bug hors chantier si un
   double clic paie deux fois).
4. Adhésions / billets dans une commande de table : dis si c'est possible ; ne change
   rien.
