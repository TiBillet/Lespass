1. **Constat (1) — pas de double avoir.** `BaseBillet/services_vente.py`
   `ecrire_la_vente_d_avoir_d_une_ligne` (l.688) : dans sa transaction, **avant**
   `ouvrir_vente`, verrouiller la ligne d'origine (`select_for_update`) et relire la
   quantité **déjà rendue** (ses avoirs `credit_notes`, remboursements Stripe compris) ;
   `quantite` > quantité restante → `ValueError` claire, rien d'écrit. Même relecture
   sous verrou dans `PaiementStripe/utils.py` `partial_refund_payment`, **avant**
   l'appel à Stripe (lignes verrouillées, quantité rendue ≤ reste). Les boutons de
   validation des trois écrans (`Administration/templates/admin/lignearticle/emettre_avoir.html`,
   `Administration/templates/admin/annulation/confirmer_annulation.html`,
   `Administration/templates/admin/membership/partials/cancel_form.html`) portent
   `data-loading-disable` (djc : sans délai, contre le double clic).
2. **Constat (2) — pas de double remboursement Stripe.** `partial_refund_payment`
   (`stripe.Refund.create`, l.153) reçoit une **clé d'idempotence**
   `remboursement-{paiement.uuid}-{n}`, où `n` = le nombre de règlements **négatifs**
   déjà écrits pour ce paiement (`Reglement`, `paiement_stripe=paiement`, montant < 0),
   lu sous le verrou du point 1. Effet : après un échec postérieur au remboursement
   (rien d'écrit), le **nouvel essai** envoie la **même** clé, Stripe renvoie le
   **même** remboursement (aucun argent de plus) et l'écriture se termine ; un
   remboursement suivant, une fois le précédent écrit, a une clé nouvelle. Le commentaire
   dit la limite : Stripe garde une clé 24 h. Vérifie dans la doc de la bibliothèque
   `stripe` installée le nom exact du paramètre (`idempotency_key=`).
3. **Constat (3) + bug n°26 — un seul appariement, par tarif (`Price`).**
   `Administration/admin_tenant.py` l.3807 (écran de l'action « billets »,
   `pricesold_ids=[billet_coche.pricesold_id]`) et `BaseBillet/models.py` l.3335
   (`cancel_and_refund_ticket`, `pricesold_ids=[ticket.pricesold_id]`) : apparier par
   `Price`, comme `cancel_and_refund_resa` (la caisse écrit la ligne et les billets sur
   deux `PriceSold`). Si `_lignes_hors_stripe(pricesold_ids=…)` doit changer de
   signature, garde un seul paramètre clair (par exemple `price_ids=`).
4. **Constat (5)** — `BaseBillet/models.py` ~l.3182-3188 : le nombre de billets actifs du
   tarif **diminue** de ce qui vient d'être crédité, à chaque ligne du même `Price`.
5. **Constat (6)** — `MOYENS_DU_CHAMP_REMBOURSE_PAR` et `choix_du_champ_rembourse_par`
   vont dans `BaseBillet/services_vente.py` (à côté de `ligne_entierement_offerte`) ;

6. **Constat (8)** — `CHANGELOG/2026-09-30-montants-entiers-D-en-ligne-avoirs.md` :
