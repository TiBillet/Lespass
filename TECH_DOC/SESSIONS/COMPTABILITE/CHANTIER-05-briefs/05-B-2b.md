## Ce que B-2b change
1. Vente ouverte dans l'`atomic` (comme B-2a) : origine caisse, point de vente,
   opérateur, client (titulaire de la carte 1), carte 1, `idempotency_key` = la clé du
   paiement.
2. Lignes par `_creer_lignes_articles_cascade(..., vente=vente)` ; recharges dans la
   même vente, avec `uuid_transaction`.
3. Règlements depuis les débits réels : un par transaction de la carte 1 (valeur de
   retour gardée : montant, `fedow_transaction_uuid`, asset, carte, wallet) ; jetons →
   `LG` ; legacy partiel → un par transaction legacy (`reference_externe`) ; complément
   → **un** règlement espèces ou CB du **reste dû** (`montant_paye_en_complement`),
   jamais la somme donnée par le client (la monnaie rendue n'est pas un règlement).
4. `encaisser_vente` en dernier ; `except EgaliteDeVenteRompue` **avant**
   `except Exception` (sinon elle part en 500), même journal d'incident avec les uuid
   legacy, écran d'erreur `hx_messages` en 409 (même message que B-2a).
5. Adhésion : inchangée (FK, effets B-0).
