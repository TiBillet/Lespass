## La règle (validée par le mainteneur) — fiche B §5, « B-3b »
Lis-la **en entier** : `TECH_DOC/SESSIONS/COMPTABILITE/CHANTIER-05-B-caisse.md` §5,
points 1 à 7 et « Décisions du mainteneur ». En bref :
1. un geste, deux vidanges : **ancien Fedow d'abord** (`card/refund`, `VOID` si « vider
   et délier », sinon `REFUND`), puis Fedow local ;
2. ancien Fedow en échec → **rien n'est fait**, message clair ; ancien Fedow réussi puis
   local en échec → journal **INCIDENT** (montant, carte, uuid), écran d'erreur ;
3. espèces rendues = monnaie locale du lieu + FED, sur les deux Fedow ; **jetons cadeau
   repris sur les deux Fedow** (local : nouveau), sans argent, sans règlement ;
4. vente `VIDAGE_CARTE` sans article : un règlement **positif** par transaction REFUND
   d'argent (`LE` / `SF` ; local → `fedow_transaction_uuid`, ancien → `reference_externe`),
   puis **un règlement espèces −total** ; Σ = 0 ;
5. carte inconnue de l'ancien Fedow, ou lieu non relié à l'ancien Fedow : vidange locale
   seule, comme aujourd'hui ;
6. lignes « Refund » (anciens lecteurs, jusqu'à H) : totaux des deux Fedow ;
7. **même carte primaire** pour les deux Fedow.
L'écran, l'aperçu et le reçu séparés et détaillés sont pour **B-3b-2** : ici, ne change
pas les gabarits ; rends seulement disponibles, dans le contexte de la vue, les données
séparées (transactions locales, transactions de l'ancien Fedow) dont B-3b-2 aura besoin.
