## La règle, en clair
1. **`laboutik.MappingMonnaie`** (nouveau) : `asset_uuid` (UUID, unique, sans FK),
   `compte_de_tresorerie` (FK `CompteComptable`, `PROTECT`). Le chargeur (E-1a) relie les
   **deux uuid du FED** (fedow_core et ancien Fedow, `fedow_public.AssetFedowPublic`) au
   467000 **s'ils existent** dans le lieu.
2. **`PointDeVente.code_journal`** : `CharField(max_length=10, blank=True)`, validé
   **lettres majuscules seules** (`RegexValidator`).
3. **Trois fonctions** dans un module du plan comptable (par exemple
   `laboutik/plan_comptable.py`), sans état, testables seules :
   - `compte_pour_reglement(moyen, asset_uuid)` (§3.1) : monnaie → moyen (seulement sans
     monnaie ou monnaie du lieu) → erreur explicite ; `SF` toujours par la monnaie ;
     `NA`, `NM` : aucune écriture (la fonction rend `None`, documenté) ;
   - `journal_pour(point_de_vente, origine)` (§3.2) : le point de vente gagne ; code
     renseigné ou dérivé du nom (lettres seules, 10) ; sinon la table des 9 origines ;
     origine inconnue → erreur ; et `collisions_de_codes_journal()` (deux points de vente,
     même code) pour E-2 ;
   - `compte_pour_article(ligne)` (§3.3, **ordre exact de la fiche** : 0 hors chiffre
     d'affaires — écarts par nom, `RE` / `RC` / `R` / `E` → 419100, `VR` → compte de la
     monnaie de la ligne — ; 1 `CR` par `consigne_remboursee` ; 2 catégorie de caisse par
     FK ; 3 mode de caisse ; 4 type de produit ; 5 erreur). Les numéros viennent d'une
     constante `COMPTE_PAR_DEFAUT`, recherchés par `numero_de_compte`.
   - Une seule exception claire pour toutes les erreurs (par exemple
     `CompteComptableManquant`, message FR avec ce qui manque : moyen, monnaie, produit,
     origine).
4. **Le CSV en ligne** (`comptabilite/csv_comptable.py` l.54 et suivantes) lit le **plan
   de la caisse** : `laboutik.MappingMoyenDePaiement` (champs `moyen_de_paiement`,
   `compte_de_tresorerie`) et `laboutik.CompteComptable` (`numero_de_compte`,
   `libelle_du_compte`) ; TVA par **taux** ; billets / adhésions par `COMPTE_PAR_DEFAUT`.
   **Rien d'autre ne change** dans ce fichier (le prorata du HT, le repli 512000 avec
   avertissement et la lecture de `rapport_json` restent : la fiche F le réécrit).
5. **Retrait de `comptabilite.CompteComptable` et `comptabilite.MappingMoyenDePaiement`**
   (modèles, admin `comptabilite/admin.py` l.342-371, imports) par une migration
   `DeleteModel`. La migration `0002` (données) **reste** dans l'historique (on ne
   supprime pas une migration appliquée) : ses lignes disparaissent avec les tables.
